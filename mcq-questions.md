# MCQ Questions - Local Observability Platform

## Instructions
Choose the best answer for each question. Each question has only one correct answer.

---

### Question 1: Observability
What is observability in software systems?

A) The ability to see the source code  
B) The ability to understand the internal state of a system from its external outputs (metrics, logs, traces)  
C) The ability to deploy software  
D) The ability to write tests  

**Answer: B**

---

### Question 2: Three Pillars
What are the three pillars of observability?

A) Code, tests, documentation  
B) Frontend, backend, database  
C) Metrics, logs, and traces  
D) CPU, memory, disk  

**Answer: C**

---

### Question 3: Metrics
What is a metric in observability?

A) A line of code  
B) A numerical measurement of system behavior over time  
C) A database table  
D) A configuration file  

**Answer: B**

---

### Question 4: Alert Threshold
What is an alert threshold?

A) The maximum number of alerts allowed  
B) A value that, when exceeded, triggers an alert  
C) The time between alerts  
D) The alert message length  

**Answer: B**

---

### Question 5: Log Levels
Which log level indicates the most severe issue?

A) INFO  
B) WARNING  
C) ERROR  
D) CRITICAL  

**Answer: D**

---

### Question 6: SLA
What does SLA stand for?

A) System Load Average  
B) Service Level Agreement  
C) Software License Agreement  
D) Secure Login Authentication  

**Answer: B**

---

### Question 7: Alert Fatigue
What is alert fatigue?

A) Alerts that run slowly  
B) When too many alerts cause responders to become desensitized and ignore them  
C) Alerts that consume too much CPU  
D) Alerts that expire  

**Answer: B**

---

### Question 8: Uptime Calculation
If a service was available for 99.5 hours out of 100 hours, what is the uptime percentage?

A) 99.5%  
B) 100%  
C) 95%  
D) 50%  

**Answer: A**

---

### Question 9: Incident Response
What is automated incident response?

A) Manually fixing all incidents  
B) Automatically detecting and responding to incidents with predefined actions  
C) Ignoring incidents  
D) Deleting incident logs  

**Answer: B**

---

### Question 10: Metric Aggregation
What does metric aggregation do?

A) Deletes metrics  
B) Combines multiple metric values into summary statistics like average or sum  
C) Encrypts metrics  
D) Renames metrics  

**Answer: B**

---

### Question 11: Log Aggregation
Why aggregate logs from multiple sources?

A) To delete logs  
B) To centralize logs for easier searching, analysis, and correlation  
C) To encrypt logs  
D) To slow down the system  

**Answer: B**

---

### Question 12: Dashboard Purpose
What is the primary purpose of an observability dashboard?

A) To make the application look professional  
B) To provide a unified view of system health, metrics, alerts, and status  
C) To replace all monitoring tools  
D) To store data  

**Answer: B**

---

### Question 13: Cooldown Period
What is an alert cooldown period?

A) Time to cool down the server  
B) Minimum time between repeated alerts for the same issue to prevent spam  
C) Time to resolve an alert  
D) Time to delete alerts  

**Answer: B**

---

### Question 14: Error Budget
What is an error budget in SLA monitoring?

A) Budget for fixing errors  
B) The allowed amount of downtime or errors before violating SLA  
C) Cost of errors  
D) Number of developers  

**Answer: B**

---

### Question 15: Proactive vs Reactive Monitoring
What is the difference between proactive and reactive monitoring?

A) Proactive is faster  
B) Proactive prevents issues before they impact users, reactive responds after issues occur  
C) Reactive is better  
D) There is no difference  

**Answer: B**
